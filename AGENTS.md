# Architecture rules
- Homepage browsing reuses the directory's shared server query builder for keyword synonyms and equivalent towns, with exact counts and alphabetical range pagination; preserve `/local` query contracts and never create a duplicate search index.
- Build the neutral homepage in `MarketFeedHome` with scoped feed styles; retain `DirectoryEditorialHome` and its components for rollback, preserving legacy routes and SEO contracts.
- Retain the original RealScout widget in an embedded homepage disclosure with its existing configuration and anchor; embedding suppresses the old headline to maintain one homepage H1.
- Keep dense-feed geometry scoped to `.nest-feed`; latest Nov 24 authorization extends shared palette only across public routes through route-scoped semantic tokens/legacy color compatibility, excluding private reports and management/auth surfaces. Retain earlier scoped-theme implementation/history without restoring its superseded public-color restriction.
- The Nov 24 authorized compact feed replaces the old search-hero/four-pillar homepage mandate; preserve the north-star/design notes and legacy designs rather than deleting them.
- Feed adapters accept edition configuration, exclude unpublished/import-preview inventory, use semantic source dates and queue polling arrivals; directory metadata never becomes a duplicate business search index.
- Only the listings adapter assigns listing-event kind; use Eastern calendar days for publication/newness and full canonical source URL plus original event day for listing/story preference, so generic Property news never gains listing badges or loses distinct events.
- Feed listing editorial highlighting reads the existing `is_featured` flag into optional saved snapshot metadata and changes only the row surface and existing badge footprint, never ordering or eligibility.
- Merge approved feed-town metadata into canonical directory town options without replacing source municipality labels, so structured listings remain filterable without a second directory index.
- Separate equivalent town filter groups from canonical destinations resolved against the county directory; both feed and `/local` query original business slugs with IN, so Bethlehem/Delmar and Glenville/Scotia records remain intact and reachable through unchanged URL contracts.
- Feed business identity uses supplied subcategory before category, never headlines; saved snapshots fall back to their existing metadata, preserving honest directory identity without invented dates.
- The homepage browse area is a town/category directory: visible featured town links plus a bounded A–Z town dialog, category links that map to existing browse types or structured business classifications (`cat`, defined in `src/lib/directoryCategories.ts` and applied by the shared query builder on subcategory, falling back to broad category only when subcategory is empty), and URL-backed view/type/cat/search; free-text search keeps its synonym semantics, and context changes reset pages, not town.
- Latest updates shows one six-row window merged across sources via `collectLatestWindow`: each source is read in bounded doubling chunks (≤200 rows) and a merged row is final only after every unfinished source has returned a row ordered at or after it, so adapter rejections and de-duplication never skip, repeat or short a page; selected-category browsing uses bounded eight-row server pages.
- Keep dated Latest updates separate from published Browse all inventory; source-specific server pages expose exact counts, active approved-link homes never use import-preview tables, and active rentals use supplied availability only, never import/publication timestamps.
- Preserve the intentional neutral `index.html` application shell; homepage-specific metadata belongs only to Index/SEOHead so legacy routes retain their fallback SEO behavior.
- Administrator roles require privileged provisioning, never first-user self-claim, to prevent account privilege escalation.
- Protect business billing and placement fields with a database trigger that permits only administrators or the service role; owners retain ordinary profile updates without granting themselves paid benefits.
- Public investment assets must satisfy `is_active = true` in database policies, matching the existing published-deal contract.
- Report/guide email handlers verify the current account with hosted auth and use only its confirmed email; resource subjects and destinations are server-owned so callers cannot repurpose these sends.
- Resource email forms share a verified-email gate and mount the retained Auth page at `/auth` with validated same-origin return paths; partner sign-in and browsing permissions remain unchanged.- Public form INSERT policies validate contact fields, lengths, initial statuses and staff-only fields through shared SQL helpers instead of `WITH CHECK (true)`, so anonymous submissions stay possible without arbitrary rows.
- Email handlers HTML-escape every visitor-supplied value, and partner referral emails require the signed-in owner of the partner record, so public endpoints cannot inject markup or impersonate partners.
- Private report contents live in a server function released only after a server-held access password check; never ship private report data, passwords or share tokens in the app bundle.
- PublicNavigation supplies click/keyboard grouped menus to the homepage and shared CleanHeader public routes; retain original section destinations in shared data and keep LegacyCleanHeader on excluded private/auth/admin routes. Header browse links preserve town/search through the existing URL state contract.
- Rental detail URLs validate UUIDs and re-fetch only active rentals into the retained public RentalDetailModal; homepage overlays retain exact browse URL state, saved snapshots use narrowly validated specific `/rentals` links, and town hrefs preserve the same context for modified clicks.
