# Nest OS — Founder-Approved Region Expansion Sequence

Status: documentation only. No region, domain, schema, route, data import, or
public page is created by this document.

## Approved order

1. **Capital District Nest** — reference implementation. Every pattern must be
   proven here before replication.
2. **Syracuse Nest** — first same-state replication. Proves the platform runs a
   second region without a schema fork or component fork.
3. **Rochester Nest** — second replication and declining-founder-effort test.
4. **Buffalo Nest** — larger Western New York scale and competition test.
5. **Berkshires Nest** — first cross-state deployment (Massachusetts).

## Massachusetts market definition

- **Public brand:** The Berkshires.
- **Canonical operating geography:** Berkshire County, Massachusetts.
- **Initial scope:** the county's approximately 30+ municipalities. The exact
  municipality count must be verified against an authoritative source before
  any public use; do not publish an approximate count.
- **Naming constraint:** this region is never called "Western Mass."
- **Umbrella allowance:** "Western Massachusetts" may later exist as an
  umbrella containing separate regional instances — Berkshires, Pioneer
  Valley, and Franklin County / North Quabbin — each with its own canonical
  geography.

## Core replication success metric

Founder hours and engineering interventions must **decline** across the
sequence: Capital District → Syracuse → Rochester → Buffalo. Each launch
records hours spent, manual steps taken, and code changes required, so the
trend is measurable rather than asserted.

## Explicit non-goal

Do not build a one-click region factory yet. Automation is earned only by
steps proven repeatedly manual and risky across at least two replications.
